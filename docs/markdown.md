# Правила Markdown

Документация Itmotify пишется в Markdown и собирается в сайт с помощью MkDocs. Большую часть правил из этого раздела проверяет markdownlint. Номер правила линтера указан в последнем столбце таблиц.

## Файлы

- Имя файла — латиницей, строчными буквами, слова через дефис: `create-playlist.md`.
- Кодировка — UTF-8, переводы строк — LF. Файл заканчивается пустой строкой.
- Каждый файл — одна страница сайта. Новую страницу добавьте в навигацию `nav` в `mkdocs.yml`.

## Разметка

| Элемент | Правило | Пример | Правило линтера |
| --- | --- | --- | --- |
| Заголовки | Только через `#`, пустая строка до и после | `## Шаги` | MD003, MD022 |
| Заголовок страницы | Один заголовок первого уровня в первой строке | `# Создать плейлист` | MD025, MD041 |
| Уровни заголовков | Без пропусков уровней | `##` → `###` | MD001 |
| Маркированный список | Маркер — дефис | `- пункт` | MD004 |
| Вложенный список | Отступ — 4 пробела | `····- пункт` | MD007 |
| Нумерованный список | Номера по порядку | `1.`, `2.`, `3.` | MD029 |
| Блок кода | Только огороженный, с указанием языка | `` ```yaml `` | MD040, MD046 |
| Ссылка | Адрес только в разметке ссылки или в угловых скобках | `[Глоссарий](glossary.md)` | MD034 |
| Изображение | С альтернативным текстом | `![Кнопка создания плейлиста](assets/images/playlist/create.png)` | MD045 |
| Жирный текст | Через две звёздочки | `**Сохранить**` | MD050 |
| Пробелы | Без пробелов в конце строки и без двух пустых строк подряд | — | MD009, MD012 |

## Особенности MkDocs

- Вложенные списки сдвигайте на 4 пробела. Python-Markdown, на котором работает MkDocs, не распознаёт вложенный список с отступом в 2 пробела.
- Ссылки на другие страницы ведите на файл `.md`, а не на адрес сайта. MkDocs сам превратит их в адреса и при сборке с ключом `--strict` проверит, что страница существует.
- Ссылка на раздел страницы — через якорь из заголовка: `[Списки](formatting.md#списки)`.
- Сочетания клавиш оформляйте как `++ctrl+s++`, а не HTML-тегами.
- HTML в Markdown не используйте. Исключение — служебные комментарии для Vale, см. ниже.

## Длина строки

Длина строки не ограничена. Пишите абзац в одну строку и не переносите его вручную: ручные переносы мешают читать изменения в Pull Request.

## Отключение проверок

Иногда текст нарушает правило намеренно, например в примерах «как неправильно». Такие примеры оформляйте зачёркиванием `~~…~~` — Vale их пропускает. Если зачёркивание не подходит, отключите конкретное правило Vale комментарием и сразу включите его обратно:

```markdown
<!-- vale Itmotify.Vague = NO -->
Текст, в котором слово «быстро» стоит намеренно.
<!-- vale Itmotify.Vague = YES -->
```

Не отключайте все правила сразу и не отключайте markdownlint для целых файлов.

## Пример

Фрагмент страницы с типичными ошибками разметки:

```markdown
Создать плейлист
================

* Откройте **Медиатеку**
  * нажмите кнопку
Подробнее: https://itmotify.example/help

![](assets/images/playlist/create.png)
```

Тот же фрагмент по правилам:

```markdown
# Создать плейлист

- Откройте **Медиатеку**.
    - Нажмите **Создать плейлист**.

Подробнее — в справке [Плейлисты](https://itmotify.example/help).

![Кнопка «Создать плейлист» в разделе «Медиатека»](assets/images/playlist/create.png)
```

Что исправлено:

- заголовок оформлен через `#` (MD003);
- маркер списка — дефис (MD004);
- вложенный список сдвинут на 4 пробела (MD007);
- вокруг списка есть пустые строки (MD032);
- голый адрес заменён ссылкой с названием страницы (MD034);
- у изображения есть альтернативный текст (MD045).
