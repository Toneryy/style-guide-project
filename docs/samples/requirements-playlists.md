# Требования к функциям: плейлисты

Фрагмент раздела ТЗ на разработку Itmotify с функциональными требованиями к работе с плейлистами. Источник всех требований — интервью с пользователями и анализ аналогов (Spotify, Яндекс Музыка), поэтому отдельного столбца для источника в реестре нет.

## Реестр требований

| ID | Требование | Приоритет | Критерий приёмки |
| --- | --- | --- | --- |
| ФТ-10 | Система должна позволять пользователю создать плейлист с названием длиной от 1 до 100 символов. | Должно | Плейлист с названием из 1 и из 100 символов создаётся, из 0 и из 101 символа — нет |
| ФТ-11 | Система должна добавлять выбранный трек в конец плейлиста не позднее 1 с после выбора плейлиста. | Должно | Автотест: 100 добавлений, 95-й процентиль времени не больше 1 с |
| ФТ-12 | Система должна позволять пользователю менять порядок треков в плейлисте перетаскиванием. | Следует | Новый порядок сохраняется после перезагрузки страницы |
| ФТ-13 | Система должна показывать публичный плейлист в профиле его владельца всем пользователям и гостям. | Следует | Публичный плейлист виден гостю, приватный — не виден |
| ФТ-14 | Система должна удалять плейлист только после подтверждения пользователем в диалоговом окне. | Должно | Без подтверждения плейлист не удаляется |
| ФТ-15 | Система должна хранить в одном плейлисте до 10 000 треков. | Может | Плейлист из 10 000 треков открывается и воспроизводится |
| ФТ-16 | Система не должна создавать у одного пользователя два плейлиста с одинаковым названием. | Должно | При попытке создать дубликат пользователь видит сообщение **Плейлист с таким названием уже есть** |

## ФТ-10. Создание плейлиста

Система должна позволять пользователю создать плейлист с названием длиной от 1 до 100 символов.

| Атрибут | Значение |
| --- | --- |
| Приоритет | Должно |
| Источник | Интервью с пользователями: 14 из 15 участников собирают собственные плейлисты |
| Критерий приёмки | Плейлист с названием из 1 и из 100 символов создаётся и появляется в **Медиатеке**; с пустым названием и из 101 символа кнопка **Создать** неактивна |
| Связанные требования | ФТ-16, НФТ-03 |
| Ограничения | Гость не может создавать плейлисты, см. ФТ-02 |

## Разбор примера

Фрагмент написан по шаблону [Требование](../templates/requirement.md) в формате реестра требований.

| Правило | Как применено |
| --- | --- |
| [Одно требование — один пункт](../requirements.md#одно-требование--один-пункт) | Создание, добавление, порядок, видимость и удаление — отдельные требования ФТ-10…ФТ-16 |
| [Формула требования](../requirements.md#формула-требования) | Субъект «Система» + «должна» + действие + объект + условие: «Система должна добавлять выбранный трек в конец плейлиста не позднее 1 с…» |
| [Модальность](../requirements.md#модальность) | Приоритеты «Должно», «Следует», «Может» совпадают с таблицей модальности |
| [Проверяемость](../requirements.md#проверяемость) | Для каждого требования есть критерий приёмки с граничными значениями: 1 и 100 символов, 0 и 101 символ |
| [Приоритет и источник](../requirements.md#приоритет-и-источник) | Источник один для всех требований и указан перед реестром |
| [Термины в требованиях](../requirements.md#термины-в-требованиях) | «Плейлист», «трек», «гость», «Медиатека» — из глоссария, без синонимов |
| [Числа](../numbers.md#числа) | «10 000» с пробелом, единицы в требованиях сокращены: «1 с» |
