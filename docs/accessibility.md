# Доступность текста

Документацию Itmotify читают разные люди. Незрячие и слабовидящие слушают ее с помощью экранного диктора. Кому-то мешает дислексия, для кого-то русский язык не родной, кто-то читает с телефона в шумном транспорте. Правила этого раздела помогают сделать текст доступным для всех читателей.

Правила опираются на два документа:

- рекомендации по доступности веб-контента [WCAG 2.2](https://www.w3.org/TR/WCAG22/) консорциума W3C. Ориентируемся на уровень AA, а для ссылок – на более строгий критерий 2.4.9 уровня AAA;
- [ГОСТ Р 52872-2019](https://tiflocentre.ru/documents/gost-r-52872-2019.php) с требованиями доступности интернет-ресурсов и приложений для людей с инвалидностью. Он основан на WCAG 2.1, поэтому в деталях может отличаться от WCAG 2.2.

Там, где наши правила строже стандартов, это сделано намеренно: документацию проще сразу писать доступной, чем исправлять потом.

## Простой язык

- Пишите короткими предложениями и общеупотребительными словами – см. [Стиль изложения](style.md).
- Расшифровывайте сокращения при первом упоминании – см. [Сокращения](spelling.md#сокращения).
- Не используйте идиомы и сленг: «на лету», «из коробки», «под капотом». Их трудно понять тем, для кого русский язык не родной, и их неверно переводят автоматические переводчики.

| Неправильно | Правильно |
| --- | --- |
| ~~Настройки применяются на лету.~~ | Настройки применяются сразу, перезапускать приложение не нужно. |
| ~~Рекомендации работают из коробки.~~ | Рекомендации не нужно настраивать: они появятся, когда вы послушаете 10 треков. |
| ~~Под капотом рекомендаций – машинное обучение.~~ | Рекомендации составляет алгоритм машинного обучения по вашей истории прослушиваний. |

## Структура страницы

- Ставьте заголовки по уровням без пропусков. Экранный диктор показывает список заголовков, и по нему читатель переходит к нужному месту страницы.
- Оформляйте списки разметкой Markdown, а не символами «•» и переносами строк. О настоящем списке диктор сообщает, сколько в нем пунктов.
- Ставьте самое важное в начало страницы и в начало абзаца.

| Неправильно | Правильно |
| --- | --- |
| ~~`####` Скачивание~~ сразу после заголовка `##` | `###` Скачивание – следующий уровень |
| ~~• Откройте Медиатеку~~ с символом и переносом строки | `- Откройте **Медиатеку**.` – пункт списка Markdown |

## Ссылки

Экранный диктор умеет показывать список всех ссылок на странице. В таком списке ссылка читается без окружающего текста, поэтому ее текст должен быть понятен сам по себе.

- Пишите в тексте ссылки, куда она ведет. Слова «здесь», «тут», «по ссылке», «подробнее» в списке ссылок ничего не значат. Vale считает такие ссылки ошибкой.
- Делайте ссылкой 2–5 слов, а не целое предложение.
- Если ссылка открывает файл, укажите формат и размер: «Тарифы Itmotify (PDF, 1 МБ)».

| Неправильно | Правильно |
| --- | --- |
| ~~Подробнее о подписке читайте здесь~~, ссылка на слове «здесь» | Подробнее – в разделе [Подписка Premium](glossary.md#продукт-и-пользователи) |
| ~~Инструкция по ссылке~~, ссылка на словах «по ссылке» | [Инструкция по созданию плейлиста](examples/create-playlist.md) |

## Изображения

- У каждого изображения есть альтернативный текст. Его проверяет markdownlint, правило MD045.
- Альтернативный текст передает смысл изображения, а не его вид. Пишите одно предложение до 150 знаков.
- Не начинайте альтернативный текст со слов «Изображение» или «Скриншот»: диктор и так сообщает, что это изображение.
- Не используйте разметку в альтернативном тексте: жирный и код в нем не отображаются. Названия элементов пишите без выделения.
- Шаги инструкции описывайте текстом, даже если на скриншоте все видно.
- Не заменяйте текст картинкой: таблицу – скриншотом таблицы, список – схемой без описания. Под схемой давайте ее текстовое описание.

| Неправильно | Правильно |
| --- | --- |
| ~~`![Скриншот экрана](assets/images/playlist/new-playlist.png)`~~ | `![Окно Новый плейлист с полем для названия и кнопкой Создать](assets/images/playlist/new-playlist.png)` |
| ~~`![Картинка 1](assets/images/playlist/more-menu.png)`~~ | `![Кнопка Еще в строке трека открывает меню с пунктом Добавить в плейлист](assets/images/playlist/more-menu.png)` |

## Цвет и положение

- Не передавайте информацию только цветом. Читатель может не различать цвета, а в темной теме цвета выглядят иначе.
- Не указывайте элемент только по положению: «кнопка справа», «ссылка ниже». Называйте элемент – см. [Положение и цвет](ui.md#положение-и-цвет).

| Неправильно | Правильно |
| --- | --- |
| ~~Нажмите зеленую кнопку справа.~~ | Нажмите **Слушать** под обложкой плейлиста. |
| ~~Треки, недоступные без подписки, выделены серым.~~ | Треки, недоступные без подписки, выделены серым и отмечены значком замка. |

## Таблицы

- У таблицы всегда есть строка заголовков. Диктор зачитывает заголовок столбца вместе со значением ячейки.
- Не используйте таблицы для верстки и не объединяйте ячейки.
- Не оставляйте ячейки пустыми, ставьте тире «–».

| Неправильно | Правильно |
| --- | --- |
| ~~Таблица из двух столбцов, чтобы поставить скриншот рядом с текстом шага~~ | Скриншот после текста шага, без таблицы |
| ~~Пустая ячейка в столбце «Ограничения»~~ | Тире «–» в ячейке: ограничений нет |

## Эмодзи и символы

- Не ставьте эмодзи в заголовки и не заменяйте ими слова. Диктор читает эмодзи по названию: «красное сердце», «огонь».
- Не пишите слова прописными буквами для выделения: диктор может прочитать такое слово по буквам.
- Стрелку «→» используйте только в пути по меню. В обычном тексте пишите словами: «затем», «после этого».

| Неправильно | Правильно |
| --- | --- |
| ~~`## 🔥 Подборка дня`~~ | `## Подборка дня` |
| ~~Ставьте ❤️ трекам, которые понравились.~~ | Ставьте отметку **Нравится** трекам, которые понравились. |
| ~~Выберите трек → он начнет играть.~~ | Выберите трек, и он начнет играть. |

## Видео и звук

- У видеоинструкции есть субтитры и текстовая версия шагов.
- Не включайте видео и звук автоматически: звук мешает слушать экранный диктор.

| Неправильно | Правильно |
| --- | --- |
| ~~Посмотрите видео, там все показано.~~ | Под видео – те же шаги текстом, у видео есть субтитры. |
| ~~Видео начинается со звуком, как только открылась статья.~~ | Видео начинается, только когда читатель нажмет **Смотреть**. |

## Чек-лист доступности

- [ ] предложения короткие, сокращения расшифрованы;
- [ ] заголовки идут по уровням без пропусков;
- [ ] текст каждой ссылки понятен без окружения;
- [ ] у каждого изображения есть альтернативный текст без разметки, а шаги описаны текстом;
- [ ] информация не передается только цветом или положением;
- [ ] у таблиц есть строка заголовков, ячейки не объединены и не пустые;
- [ ] в заголовках и вместо слов нет эмодзи.
